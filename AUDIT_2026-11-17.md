# Project Audit — 2026-11-17

The whole project was reviewed in five parts. No fixes or other code changes were made, and no tests or servers were run as part of this audit.

## Overall finding

The connections between the parts are healthy. All approximately 310 frontend API calls match the backend's 344 routes with the correct path and method. There are no dead page links or broken imports, and both WebSocket connections match.

The issues found are primarily logic problems, with the most serious concentrated in payments.

## High severity

All three high-severity findings are in payments.

1. **Money can be taken while the fee remains "Processing".** If the client presses Pay twice, the second press replaces the payment tracker. The webhook for the first payment is then ignored. (`payment_service.py:301-310`, `payment_service.py:448-456`)
2. **A failed payment cannot be retried.** The message says "Please try again", but checkout refuses any payment whose status is `failed`, and the UI shows no Pay button. (`payment_service.py:297`, `ModTracking.jsx:1264`)
3. **Cancelling a subscription removes paid features immediately.** The stated behavior is access until the period ends, but `get_tier()` treats a cancelled plan as free at once. (`subscription_service.py:84-90`, `subscription_service.py:162-181`)

## Medium severity

4. **Engagement status changes are unchecked writes.** `set_status` filters on `_id` only. If the client presses Accept while the lawyer withdraws, the case stays with the lawyer but the engagement shows `declined`. Complete and terminate then both fail. (`engagement_repo.py:114-122`)
5. **A past reviewer can read other lawyers' notes.** Lawyer A can still see the client's note to lawyer B and B's rejection note on the document page. (`documents_v2.py:325-334`, `documents_v2.py:1061-1071`)
6. **An admin changing a client to a lawyer breaks the account.** `lawyer_profile` remains null, so every profile or onboarding save fails with a 500. (`admin_service.py:337-361`, `user_service.py:107`)
7. **A second annotator's label crashes.** The unique index is on `request_id` alone, but labels are saved per `request_id` and labeller. Inter-annotator agreement (alpha) can therefore never be computed. (`indexes.py:617`, `labeling_service.py:140`)
8. **Lawyer Dashboard counts disagree with the Appointments page.** Once a request passes its `expires_at`, the counts drop it even though expiry is disabled. The Appointments page still shows it and Accept still works. (`lawyer_actions.py:43-44`)
9. **Client chat can permanently miss an answer after a connection drop.** After reconnecting, the client asks for the answer once, receives `pending`, and never asks again. It then says it stopped waiting even though the answer was saved. (`ModChatbot.jsx:345-402`, `chat_socket.py:1215`)
10. **Lawyer research automatic retry fails on `busy` (409), or runs the AI a second time after a timeout.** (`AILegalPage.jsx:1061`, `attempt.js:98`)
11. **`/ai/query` is open to every role with no rate limit, and no screen uses it.** (`ai.py:278`, `ai.py:991`)
12. **Withdrawing a resubmitted approved document erases its `approved` status.** (`document_transitions.py:641-645`)
13. **Fee settlement is not atomic.** If the server crashes between the two writes, the payment remains pending forever. (`payment_service.py:405-422`)
14. **Re-subscribing while a plan is active resets its end date.** The subscriber loses the remaining paid time. (`subscription_service.py:94-139`)
15. **Case-law search blocks the server.** A synchronous embedding call runs inside an async function. (`citator_service.py:454`)
16. **The mock payment webhook is unsigned.** It is used whenever the Safepay key is empty, including outside dry-run mode. (`payments/__init__.py:14`, `mock.py:30`)
17. **The `/plans` page promises a seven-day free trial and "change next cycle", but the backend implements neither.** (`plans/page.jsx`)
18. **A quick-review request stuck in `accepting` blocks that document forever.** This is plausible and requires a crash during acceptance. (`quick_review.py:335-385`)

## Low severity

- Intake shows "Case analysis complete" even when the law-library search failed. A real 500 makes the client wait three minutes for nothing. (`ModIntake.jsx:1486`, `ModIntake.jsx:1554`)
- Clicking a lawyer's quick-review or agreement notification goes nowhere or opens the dashboard. (`notificationTarget.js:28-62`)
- Instant Documents always shows "Generation failed" instead of the server's message. `ModTools.jsx:710` reads `.detail`, but the error is in `.message`.
- `terms_withdrawn` is never sent to the client, so a lawyer withdrawing terms appears as `declined`. A system cancellation appears as "You withdrew". (`schemas/engagement.py:71`, `ModLawyers.jsx:2507`)
- "Request to Hire" remains clickable while that lawyer's terms are waiting. (`ModLawyers.jsx:627`)
- The case meeting card has no Join link without a Daily key. (`case_consultations.py:36`)
- The `/touch` contact form sends nothing.
- `/admin/account-settings` and `/admin/analytics` open the Dashboard.
- The change-password message omits the uppercase-letter requirement. (`user_service.py:74`)
- The Pay button fails silently.
- Each payment-failed retry sends another notification.
- Voice upload reads the entire file into memory before applying the 10 MB check. (`voice.py:32`)
- `POST /cases` accepts any role.
- Clarify accepts a whitespace-only answer and spends an LLM call on an intake that has already been converted.
- Some graph-routing code is dead. (`edges.py:44`, `edges.py:155`, `edges.py:236`)
- Thirty-two backend routes have no screen calling them, including labelling, admin retention, and analyzer playbooks.

## Healthy areas

- **Authentication and sessions:** login, verification and reset tokens, WebSocket tickets, and admin guards.
- **Appointment status machine:** versioned writes and unique slot indexes.
- **Document access:** revision pinning, Vault transactions, case-file and analyzer ownership checks, and agreement privacy.
- **Data separation:** intake and conversation ownership checks.
- **Secrets:** no secrets were found in tracked source code.

## Second check — 2026-11-18 (independent review of commit 7768eae)

An independent reviewer found 8 gaps in the first round of fixes; all are now fixed (uncommitted, on top of 7768eae):
1. A stored payment failure could dedupe the later success when the provider reuses one event id → failure events are keyed `<id>:failed`.
2. A FAILED fee never expired, so it could be paid after its deadline → FAILED now expires like CREATED/PENDING.
3. A late failure from an old checkout failed the current attempt → failures for a superseded tracker are ignored (successes from any tracker still settle).
4. Two plan checkouts opened while on Free could both be paid, and the second cut the first's period → `activate()` never shortens a running paid period, whatever the tier.
5. Withdrawing back to "approved" left the withdrawn request's note and a duplicate history entry → the approver's and client's notes are restored and the duplicate removed.
6. Quick-review recovery could reopen a request already sent → it also checks the submission's idempotency receipt.
7. Chat resume could show the same answer twice → a repeated answer (same request id) is ignored.
8. Research waited 150 s on a 409 that can never clear → it waits only on the "still being answered" 409.

Also found and fixed while there: client/lawyer notes went into an update pipeline unescaped, so a note starting with `$` was read as a field path → wrapped in `$literal`.

New tests: 4 more in `test_audit_2026_11_17_fixes.py` (19 total), 3 in `test_v2_multi_cycle_review.py`. Re-run one file at a time on the replica set: audit fixes, payments, webhook, fee billing, quick review, 8 document-review files — all pass; chat/research frontend tests pass.
